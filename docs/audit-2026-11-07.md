### T3 テスト一件ずつの評価

テストを足してよいのは CLAUDE.md の 3 つだけ:安全の約束(S)、実機・実 OS の記録(R)、見つかった回帰(G)。
一件ずつ、目的がどれかと、次の形の欠陥が無いかを見る。

| | 欠陥の形 | 見分け方 |
|---|---|---|
| D1 | 実装の追認 | 期待値がコードの写し(文言の打ち直し、定数、内部の構造)で、振る舞いが壊れても通る |
| D2 | 作り話の出力 | 実機・実 OS の出力を読む処理を、作った出力で確かめ、`assumed` の印が無い |
| D3 | 弱い確認 | 約束が破れても通る(語があるかだけ見る、否定の場合が無い、別の層を見ている) |
| D4 | 環境への依存 | 開発者の環境・時刻・順序・OS で結果が変わり、その理由の skip も無い |
| D5 | 名前・説明の不一致 | 名前や説明が、確かめている以上を言う |
| D6 | 重複 | 同じ経路の同じ約束を、別の約束なしに何度も確かめる |
| D7 | 目的が無い | S・R・G のどれでもない |

欠陥のある件は再現(約束を壊したコードで通ってしまうことを確かめる)してから「確定」にし、直す。再現には変異を使った:
約束を 1 つ壊す変更をテストの外から当て(pytest のプラグイン)、守るはずのテストが通ってしまうかを見る。
