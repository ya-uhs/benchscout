## 判断の基準(design.md §0、§3、§5、§6、§12 の 11-04・11-06 の決定から)

| | 基準 | 違反の形 |
|---|---|---|
| C1 境界 | 機器・通信方式・フレーミング・コマンド・ログの意味はエージェントの知識。コアは選択・承認・占有・実行・記録・停止の共通経路 | コアの実装がエージェントにできることの上限になる。コアが出力に意味を付ける |

| C7 説明の正しさ | エージェントが読む説明、パネルの文言、設計書・README・CLAUDE.md が実装と一致 | 古い規則の案内、実装より強い主張 |

| C9 構造 | 依存の向き、一つの概念に一つの置き場 | 非公開メソッドへの依存、同じ考えの重複 |

### T3 テスト一件ずつの評価

テストを足してよいのは CLAUDE.md の 3 つだけ:安全の約束(S)、実機・実 OS の記録(R)、見つかった回帰(G)。
一件ずつ、目的がどれかと、次の形の欠陥が無いかを見る。

| | 欠陥の形 | 見分け方 |
|---|---|---|
| D1 | 実装の追認 | 期待値がコードの写し(文言の打ち直し、定数、内部の構造)で、振る舞いが壊れても通る |

| D5 | 名前・説明の不一致 | 名前や説明が、確かめている以上を言う |
| D6 | 重複 | 同じ経路の同じ約束を、別の約束なしに何度も確かめる |

| ファイル | 確かめたこと |
|---|---|
| winjob.py | 一時停止で起動し、ジョブに入れてから動かす(子が先に逃げない)。ジョブを閉じると中の全プロセスが終わる。渡すハンドルは標準入出力だけ。止めるときは全プロセスの終わりを 5 秒待ち、終わらなければ例外で、execution.py が `stop_failed` として占有を手放さない。Windows の実機ではこの回に動かしていない |
| winusb_strings.py | 構造体の位置を usbioctl.h と照らした(USB_NODE_CONNECTION_INFORMATION_EX は 1 バイト詰め:DeviceIsHub 24、ConnectionStatus 31。USB_NODE_INFORMATION の bNumberOfPorts 6。要求は ConnectionIndex の後に SetupPacket)。言語は USBView と同じ 0x0409 固定:英語の文字列を持たない機器は名前が取れず、WMI の名前になる(不明は不明のまま)。読めないハブは飛ばす |
| runtime.py | POSIX:利用者だけが開けるフォルダのソケット。/tmp に落ちたとき、別の利用者が先に作ったフォルダは chmod が失敗して起動が止まる(大きな声で失敗する)。Windows:名前付きパイプの名前は予測できる。同じ PC の別アカウントが先に同じ名前で作ると、コアは起動に失敗し(最初のインスタンス指定)、中継はそちらにつながる。そのアカウントのプログラムはエージェントに道具の説明を渡せるが、コアの承認には触れない。複数アカウントの Windows で確かめていない:残り → 2026-11-15 VM で確認。別アカウントが先に名前を取ると、管理者は開けて鍵の照合で断り、一般の利用者は開けない(アクセス拒否)。後者を「誰もいない」と読んでいたのを直した(コアは理由を言って起動せず、中継は取られたと言う) |
| panel.ts | 表示する値はすべて `esc` を通す(属性は二重引用符)。エージェントの Markdown はエスケープの後に一部だけ戻す(テストあり)。CSP は nonce のスクリプトだけ |
| agents/acp.ts | SDK 2.2.0 のコードで、プロンプトの失敗・エージェントの終了が `nextUpdate()` の失敗になり、「起こせませんでした」のカードになることを確かめた。許可の問い合わせは表示名だけなので、benchscout の道具も人に聞く(安全側) |
| packaging/build_core.py、entry.py | 固めた中身を実行時の依存の許可一覧で確かめる(U11)。シンボリックリンクがあれば止まる |
| .github/workflows/test.yml | push は Linux 1 本、残りは手動(方針どおり)。actions はタグ指定で SHA 固定ではない(非公開のリポジトリ、受け入れ)。→ 2026-11-11 公開リポジトリにしたので、push と PR で 3 OS を回し、actions はリリースのコミットに固定した。同梱の openFPGALoader の版が違えばビルドが止まる |
| vscode/scripts/e2e.mjs | 挿し抜きで書き込む機器の欄は OS が返す欄だけ(#41 の検査を通る) |

## 残り

- 記録の無いテスト(assumed)の残り:Windows の Tang Nano の 1 件は記録(FTDI の ARM64 ドライバ、利用者が FTDI のサイトから取得)から組み直した

  文字が付かなかった)。macOS の 1 件は対象外。Zephyr のプロンプト、メーカーだけ答える道具は、その機器が要る
- ドライバの無い FT2232 は、ハブ経由の文字列要求にシリアル番号しか答えない(言語一覧・メーカー名・製品名は ERROR_GEN_FAILURE)。ドライバを
  入れると全部答えた(VM の受け渡しの問題ではなかった)。ドライバの無い間は SIPEED の配線が当たらず、不明な機器として慎重に扱われる
- #42:Linux は VM で確かめた(libftdi・libusb・hidapi の文面がそろう)。Windows は MSYS2 のパッケージの中身の一覧で照らし、libstdc++ の
  文面が拾われていなかったのを直した。→ 2026-11-13 以降、公開リポジトリの CI の package ジョブ(4 種)で毎回通っている。LGPL のソースも
  .vsix の横に置く(2026-11-15)
- 利用者の判断が要るもの:起こしたエージェントには利用者自身の他の MCP(Gmail、カレンダーなど)も読み込まれる(`claude -p` の記録)。

  道具を 1 つ拒否するとその回の調査を終える(記録)→ 2026-11-10 に直した(benchscout が続きを頼む。design.md §12)
